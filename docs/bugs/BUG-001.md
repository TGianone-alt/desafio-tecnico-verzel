# BUG-001 — Frete de R$ 19,90 é cobrado quando o subtotal é exatamente R$ 200,00 (deveria ser grátis)

| Campo | Valor |
|---|---|
| **Severidade** | Alta *(valor cobrado errado, mas só no valor exato do limite; por isso não é Crítica)* |
| **Prioridade sugerida** | Alta |
| **Classificação** | Bug |
| **Camada** | API (`/api/carrinho/calcular`) e interface (tela do carrinho) |
| **Cenário relacionado** | CT-FRE-02, CT-FRE-05 (critérios CA06 e CA08) |
| **Ambiente** | https://verzel-store.qa-test-verzel-store.workers.dev · versão 2.3.0 · Google Chrome (versão _preencher_) · Windows · 06/10/2026 (API e automação) e 07/10/2026 (interface) |
| **Status** | Aberto |
| **Reproduzível?** | Sempre (API: 5 chamadas na automação + 1 manual; interface: reproduzido com e sem cupom) |

## Pré-condições
Nenhuma. O cálculo da API não depende de estado, e na interface o carrinho começa vazio.

## Passos para reproduzir
**Pela interface**
1. Abrir a loja e adicionar 2 unidades de "Mochila Urbana 20L" ao carrinho (R$ 100,00 cada; o carrinho mostra quantidade 2 e R$ 200,00).
2. Abrir o carrinho e observar o "Resumo do pedido" (frete, total e o aviso abaixo do total).
3. Digitar o cupom `bemvindo10` no campo de cupom e clicar em "Aplicar cupom". Observar o resumo de novo.
4. Remover o cupom, clicar em "Finalizar compra", preencher nome, e-mail e CEP válidos (ex.: Maria Silva, maria@exemplo.com, 01310-100) e confirmar. Observar o resumo da tela "Pedido confirmado".

**Pela API**
1. Enviar `POST /api/carrinho/calcular` com `{"itens":[{"produtoId":"P005","quantidade":2}]}`.
2. Observar `frete`, `freteGratis` e `total`. Repetir com `"cupom": "BEMVINDO10"` e com `{"produtoId":"P008","quantidade":4}` (outra combinação de R$ 200,00).

## Resultado esperado
CA06: *"O frete é grátis para compras com subtotal a partir de R$ 200,00, inclusive."* Com subtotal de R$ 200,00: frete R$ 0,00 e total R$ 200,00; com `BEMVINDO10` (desconto de R$ 20,00), total R$ 180,00 (CA08: a regra de frete considera o subtotal antes do desconto).

## Resultado obtido
**Interface (tela do carrinho)**
| Situação | Subtotal | Desconto | Frete (esperado R$ 0,00) | Total (esperado) |
|---|---|---|---|---|
| Sem cupom | R$ 200,00 | R$ 0,00 | **R$ 19,90** | **R$ 219,90** (R$ 200,00) |
| Com `bemvindo10` | R$ 200,00 | − R$ 20,00 | **R$ 19,90** | **R$ 199,90** (R$ 180,00) |

Nas duas situações a tela exibe o aviso **"Faltam R$ 0,00 para o frete grátis."** e, ao mesmo tempo, cobra o frete. A mensagem diz que não falta nada, mas o frete continua sendo cobrado, e a tela nunca indica frete grátis.

**Pedido confirmado (interface)**
Finalizando a compra com 2 Mochilas (subtotal R$ 200,00) e dados válidos, a tela "Pedido confirmado" (pedido `VZ-566835`) registra **Frete R$ 19,90** e **Total R$ 219,90**. Ou seja, o valor errado não fica só no carrinho: ele chega ao pedido confirmado.

**API**
| Cenário | Campo | Esperado | Obtido |
|---|---|---|---|
| 2×P005, sem cupom | `frete` / `freteGratis` / `total` | 0 / true / 200 | **19.9 / false / 219.9** |
| 4×P008, sem cupom | `frete` / `freteGratis` / `total` | 0 / true / 200 | **19.9 / false / 219.9** |
| 2×P005 + BEMVINDO10 | `frete` / `freteGratis` / `total` | 0 / true / 180 | **19.9 / false / 199.9** |

Nesses casos `subtotal` (200), `desconto` (0 ou 20) e `valorFaltanteFreteGratis` (0) vieram corretos; a resposta fica contraditória, pois informa que falta R$ 0,00 e mesmo assim cobra o frete.

A interface chama `POST /api/carrinho/calcular` (200 OK) e exibe o que a API devolve, o que é coerente com a documentação ("os cálculos são feitos pela API e a interface apenas exibe o resultado"). Por isso a causa provável está na API.

Subtotais vizinhos se comportam corretamente: R$ 199,90 e R$ 199,80 cobram frete; R$ 229,90, R$ 250,00 e R$ 299,50 têm frete grátis. Hipótese: o limite está sendo comparado com `>` em vez de `>=`.

## Observações
- A própria loja anuncia na página inicial: **"Frete grátis a partir de R$ 200,00."** (print `BUG-001_05`), o que confirma a regra do ponto de vista do cliente.
- A interface sabe exibir o frete grátis: com subtotal de R$ 299,50 a linha de frete mostra **"Grátis"**. Com subtotal de exatamente R$ 200,00, mostra R$ 19,90.
- Impacto: o cliente cuja compra totaliza exatamente R$ 200,00 paga R$ 19,90 a mais do que a regra prevê, e o valor errado é registrado no pedido confirmado (`VZ-566835`). Com o cupom, o total é R$ 199,90 em vez de R$ 180,00.
- Testes automatizados que falham por este bug: `tests/api/calculo.spec.ts` → CT-FRE-02 (2 testes), CT-FRE-05 (subtotal 200,00 com cupom) e CT-CAL-01.
